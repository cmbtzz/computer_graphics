# 3D VTK查看器插件化完整开发&运行标准步骤（基于提供的正确全套代码）
## 一、前置准备
### 1. 依赖安装
```bash
pip install PyQt5 vtk pyyaml
```
### 2. 固定标准目录结构（必须严格一致，自动扫描逻辑依赖该结构）
```
3d_viewer_framework/
├─ main.py                      # 程序唯一启动入口，自动扫描插件、读取yaml配置
├─ plugin_config.yaml           # 功能开关配置，支持#注释
├─ core/
│  └─ viewer_3d.py              # 3D查看器内核（固定底层底座，禁止修改扩展逻辑）
├─ plugins/
│  ├─ base_plugin.py            # 插件统一抽象基类（所有插件父类）
│  ├─ plugin_light.py           # 光照功能插件示例
│  └─ plugin_texture.py         # 纹理贴图功能插件示例
└─ data/texture/                # 纹理素材目录（纹理插件读取图片资源）
```

## 二、分模块开发步骤（按开发顺序）
### 步骤1：编写插件抽象基类 `plugins/base_plugin.py`（统一插件规范）
1. 定义父类 `Base3DPlugin`，作为所有业务插件的统一接口；
2. 强制子类定义类属性 `plugin_cls_name`（YAML配置唯一标识，自动扫描匹配关键字）；
3. 定义4个生命周期钩子函数，内核自动分发事件：
   - `create_ui()`：**必须重写**，创建插件专属UI面板，返回QWidget；
   - `on_model_loaded(obj_path, actor, polydata)`：加载OBJ模型后自动触发；
   - `on_window_resize()`：窗口缩放时触发；
   - `on_destroy()`：程序关闭时释放资源；
4. 构造函数统一接收全局上下文 `viewer_ctx`，插件通过 `self.ctx` 共享内核渲染、模型、UI状态。

### 步骤2：开发内核底座 `core/viewer_3d.py`（固定底层，仅基础功能）
1. 封装全局状态容器 `ViewerContext`，统一存储渲染器、当前模型、信息面板等共享数据；
2. 主窗口 `VTKViewerCore` 只保留基础能力：文件树、OBJ纯白加载、VTK渲染、坐标轴、底部信息栏；
3. 提供插件注册入口 `register_plugin(plugin_cls)`：
   - 实例化插件，传入全局上下文ctx；
   - 调用插件`create_ui()`生成面板，挂载到窗口右侧统一扩展区域；
4. 事件分发机制：
   - 加载模型完成后，遍历所有插件执行`on_model_loaded`；
   - 窗口缩放`resizeEvent`遍历插件执行`on_window_resize`；
   - 窗口关闭`closeEvent`遍历插件执行`on_destroy`；
5. 布局预留右侧垂直容器，所有插件UI自动垂直堆叠，无需修改内核布局代码。

### 步骤3：开发业务功能插件（以plugin_light.py / plugin_texture.py为例，通用4步）
#### 3.1 导入依赖
插件独立导入自身使用的Qt/VTK类，**不依赖内核导入**，缺失布局控件会触发`NameError`；
示例纹理插件头部：
```python
import os
from PyQt5.QtWidgets import QWidget, QScrollArea, QGridLayout, QPushButton, QVBoxLayout
from PyQt5.QtCore import Qt, QSize, QTimer
from PyQt5.QtGui import QPixmap, QIcon
import vtk
from plugins.base_plugin import Base3DPlugin
```

#### 3.2 定义插件类，继承基类，配置唯一标识
```python
class TexturePlugin(Base3DPlugin):
    # 关键：yaml配置填写该字符串，自动扫描匹配插件
    plugin_cls_name = "texture_mapping"
    plugin_name = "texture_mapping"
    plugin_desc = "纹理贴图功能插件"
```

#### 3.3 重写生命周期钩子函数
1. **必写 `create_ui()`**：创建插件内部所有控件、布局，最终返回面板`self.plugin_panel`；
2. 按需重写回调：
   - `on_model_loaded`：模型加载完成自动应用纹理/光照参数；
   - `on_window_resize`：窗口缩放刷新纹理缩略图尺寸；
   - `on_destroy`：资源释放（无特殊资源可省略）。

#### 3.4 业务逻辑隔离，通过全局上下文交互内核
所有纹理映射、光照材质调节、VTK渲染逻辑全部写在插件内部；
通过`self.ctx`读取/操作全局共享资源：
- `self.ctx.vtk_renderer`：VTK渲染场景
- `self.ctx.current_actor`：当前加载的模型Actor
- `self.ctx.info_display`：底部信息输出文本框

### 步骤4：编写配置文件 `plugin_config.yaml`（功能开关，无需修改代码）
1. 语法支持`#`单行注释，教学场景友好；
2. `active_plugins`数组填写插件定义的`plugin_cls_name`字符串；
3. 注释/删除条目即可关闭对应插件，新增功能仅追加一行标识；
示例：
```yaml
# 启用插件列表，注释行代表关闭该插件
active_plugins:
  - texture_mapping   # 纹理贴图插件
  - light_control     # 光照材质调节插件
  # - model_measure   # 测距插件（取消注释启用）
```

### 步骤5：编写统一启动入口 `main.py`（固定模板，后续新增插件无需改动）
#### 核心逻辑分段说明
1. 路径预处理：将项目根目录加入Python搜索路径，解决相对导入报错；
2. `auto_scan_plugins()` 自动扫描插件机制（核心）：
   - 遍历`plugins`文件夹所有`.py`文件，跳过`base_`开头文件；
   - 使用`importlib`动态导入模块；
   - 筛选继承`Base3DPlugin`、存在`plugin_cls_name`的合法插件类；
   - 自动生成 `{plugin_cls_name: 插件类}` 映射字典，无需手动维护映射表；
3. 读取YAML配置容错处理：
   - 文件不存在/解析异常时，自动加载全部扫描到的插件；
4. 批量注册插件：
   - 遍历yaml配置内的插件标识，匹配映射表调用内核`register_plugin`；
   - 不存在的插件标识打印警告，不中断程序运行；
5. 初始化Qt窗口、展示界面、启动事件循环。

## 三、新增自定义插件完整流程（全程不修改main.py、core内核）
1. 在`plugins/`目录新建`plugin_xxx.py`；
2. 头部导入依赖，继承`Base3DPlugin`，定义唯一`plugin_cls_name`；
3. 实现`create_ui()`，按需重写`on_model_loaded`/`on_window_resize`钩子；
4. 修改`plugin_config.yaml`，在`active_plugins`中添加插件的`plugin_cls_name`；
5. 项目根目录执行`python main.py`，程序自动扫描、加载、挂载插件UI。

## 四、标准运行校验流程（保证程序正常加载插件）
1. 终端切换到项目根目录 `3d_viewer_framework`；
2. 执行启动命令：`python main.py`；
3. 控制台校验输出：打印`已加载插件: xxx`，无警告日志；
4. 窗口界面校验：右侧垂直区域自动渲染所有启用插件的UI面板；
5. 功能回调校验：
   - 点击左侧OBJ文件加载模型，自动执行插件`on_model_loaded`逻辑；
   - 拖拽窗口缩放，纹理缩略图自动重绘（触发`on_window_resize`）；
6. 关闭窗口：自动执行所有插件`on_destroy`资源释放。

## 五、插件架构核心约束（避坑关键点）
1. 插件不能直接修改`core/viewer_3d.py`代码，所有扩展逻辑隔离在plugins文件夹；
2. 每个插件必须独立导入自身使用的Qt/VTK控件，不能复用内核导入；
3. `plugin_cls_name`全局唯一，YAML配置必须与插件类定义完全一致；
4. 插件UI面板统一由内核挂载至右侧容器，插件内禁止新建顶层窗口；
5. 所有模型、渲染器、日志输出统一通过`self.ctx`访问，禁止插件全局变量存储模型数据；
6. 插件文件名不能以`base_`开头，自动扫描逻辑会跳过该类文件。

## 六、该插件架构对比传统硬编码程序优势
1. **开闭原则**：新增功能只新增插件文件+修改yaml，内核、启动入口永久不变；
2. **配置驱动**：YAML支持注释，教学时可直观开关功能，无需改动代码；
3. **自动扫描**：无需手动导入插件类、维护插件映射字典，减少人为漏写错误；
4. **统一生命周期**：内核统一分发模型加载、窗口缩放、关闭事件，插件无需重复绑定信号；
5. **低耦合隔离**：单个插件异常不会导致整个查看器崩溃，功能模块完全解耦；
6. 可轻量化部署：注释yaml内插件条目即可剔除多余功能，实现极简基础查看器。
